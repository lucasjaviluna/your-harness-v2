# ADR-012 — Recuperación explícita de Apply interrumpido

- **Estado:** Proposed
- **Fecha:** 2026-09-15
- **Decisión:** un `applying` interrumpido se reconcilia mediante observación read-only y decisión HITM explícita; nunca se presume éxito ni se reejecuta automáticamente.

## Contexto

Un proceso puede terminar después de iniciar la materialización y antes de registrar su resultado. El estado `applying` no demuestra si el proveedor persistió el Change completo, parcialmente o no lo hizo.

## Contrato

`reconcileInterruptedChangeApply` compara el digest actual observado en el proveedor con el digest final esperado y, cuando está disponible, con el digest base:

- digest final → `already-materialized`, recomendación `materialized`;
- digest base → `not-materialized`, recomendación `apply-failed`;
- cualquier otro digest → `inconsistent`, recomendación `recovery-required`.

La clasificación no escribe ni ejecuta nada. La promoción a `materialized` o `apply-failed` requiere una decisión HITM posterior. Un estado inconsistente queda bloqueado hasta revisión humana.

## Consecuencia

Se agrega `recovery-required` al estado operacional de Apply. La policy permite `applying → recovery-required` y sólo permite salir hacia `materialized` o `apply-failed`; el handoff, las aprobaciones y las auditorías históricas permanecen inmutables.
