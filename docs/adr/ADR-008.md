# ADR-008 — User-Selectable SDD Providers and Runtimes

- **Status:** Accepted
- **Date:** 2026-09-12

## Context

ADR-001 establishes a replaceable Specification Engine boundary and named OpenSpec as
the initial implementation. ADR-002 establishes a replaceable Agent Runtime boundary
and treats Pi as a candidate rather than a selected default.

YH must let the user choose the SDD provider and runtime appropriate to a project or
execution. A provider or runtime must not become mandatory merely because it is the
first adapter implemented. OpenSpec remains an important semantic reference, and Pi
remains a supported runtime adapter, but neither defines YH's engineering model.

## Decision

### SDD provider selection

OpenSpec is optional. It may be offered as a supported SDD provider, alongside a
future YH-native provider or other compatible providers. The active provider is a
project/workspace-level user choice resolved outside the domain model.

YH must expose available providers and fail clearly when the selected provider is
unavailable or not configured. Provider identifiers and artifacts remain behind the
`SddProvider` Application boundary defined by ADR-006.

### Runtime selection

Pi is optional. A runtime is selected by the user for a project or execution through
Application/CLI configuration, not by domain aggregates or `ExecutionRequest`.

YH must expose available runtime adapters and fail clearly for unavailable choices.
The generic work-item execution path must not permanently hard-code Pi. Until the
runtime-selection capability exists, the current Pi-backed command is an explicit
prototype path rather than a product-wide runtime default.

### Selection boundaries

```text
User / project configuration
       │
       ├── selected SDD provider ──> SddProvider ──> Engineering Core
       │
       └── selected runtime ───────> RuntimePort ──> Execution
```

Neither selection crosses the Runtime Boundary as a domain aggregate or changes the
neutral `ExecutionRequest` contract.

## Consequences

- ADR-001 is amended only with respect to OpenSpec selection: OpenSpec is optional,
  not a mandatory initial implementation.
- ADR-002's runtime independence is reinforced: Pi is not the default architecture,
  even if it is the first concrete adapter.
- A provider/runtime registry or equivalent composition mechanism is required before
  generic CLI selection can be delivered. The runtime half is now implemented by the
  composition-level `RuntimeRegistry`; project-level configuration remains open.
- The CLI's generic execution route no longer hard-codes Pi: `fake` is the default and
  Pi is registered only when explicitly selected.

## Non-Goals

This ADR does not select a configuration syntax, implement registries, install
providers/runtimes, define a YH-native provider or runtime, or make an unavailable
adapter appear selectable.

## Decision Summary

OpenSpec and Pi are optional integrations. YH will let users select from the SDD
providers and runtime adapters that are available for their project or execution.
