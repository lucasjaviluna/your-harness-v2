# Contributing to Your Harness

Thank you for your interest in contributing to Your Harness.

Your Harness is an open-source engineering platform built around explicit engineering practices, specification-driven development and human-centered governance.

This document describes the contribution process followed by the project.

---

# Before You Start

Before contributing, please read the following documents in order:

1. README.md
2. FOUNDATION.md
3. Vision
4. Engineering Charter
5. Governance
6. YDL
7. YDS
8. YGov

These documents define the engineering principles that guide every contribution.

---

# Contribution Principles

Every contribution should:

- Solve a clearly identified problem.
- Be understandable.
- Be reviewable.
- Be traceable.
- Respect the project's governance.
- Maintain consistency with the existing architecture.

---

# Contribution Workflow

Every contribution follows the same engineering workflow.

```text
Intent
    ↓
Work Item
    ↓
Specification
    ↓
Review
    ↓
Approval
    ↓
Implementation
    ↓
Verification
    ↓
Merge
```

No implementation should bypass this workflow.

---

# Pull Requests

A Pull Request should:

- Have a clear objective.
- Focus on a single Work Item whenever practical.
- Include the necessary documentation updates.
- Be ready for review before requesting approval.

Large changes should be divided into smaller, reviewable increments.

---

# Documentation

Documentation is considered a first-class artifact.

Whenever implementation changes behavior, the corresponding documentation should be updated as part of the same contribution.

---

# Reviews

Reviews exist to improve quality, maintain consistency and protect the long-term evolution of the project.

Feedback should focus on:

- Correctness
- Clarity
- Maintainability
- Consistency
- Engineering quality

Reviews should always be constructive and respectful.

---

# Code Quality

Contributors are expected to:

- Write readable code.
- Prefer simplicity over unnecessary complexity.
- Avoid premature optimization.
- Follow the established architecture.
- Keep changes focused.

---

# Communication

Engineering decisions should be documented through the project's defined process.

Discussion is encouraged before implementing significant changes.

---

# Code of Conduct

All contributors are expected to collaborate respectfully and professionally.

Constructive disagreement is welcome.

Personal attacks, disrespectful behavior or harassment are not acceptable.

---

# Thank You

Every contribution helps improve both the project and the engineering practices it promotes.

Thank you for helping build Your Harness.
